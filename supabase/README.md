# Supabase для каталогу «Наші двері»

> SEO-стан: основний домен сайту — `https://nashidveri-uzhhorod.com.ua`. Він уже підключений у Vercel; `NEXT_PUBLIC_SITE_URL` задано для Production і Preview без завершального `/`.

1. Увійдіть на [Supabase](https://supabase.com/dashboard) і натисніть **New project**.
2. Назва: `nashi-dveri`; регіон — найближчий європейський; пароль бази збережіть у надійному місці.
3. Після створення відкрийте **SQL Editor** → **New query**, скопіюйте вміст `schema.sql` і натисніть **Run**.
4. У **Project Settings → API** скопіюйте `Project URL` та `Publishable key` (або `anon` key).
5. Додайте їх у Vercel: **Project → Settings → Environment Variables**. Назви змінних наведені в `.env.example`.

Не передавайте і не додавайте в GitHub `service_role` key або пароль бази даних. Для сайту використовується лише публічний ключ.

Після цього наступним кроком перенесемо 363 моделі та їхні фото в `catalog-images`, а сайт почне брати каталог із Supabase.

## Адмінка каталогу

- Закрита сторінка: `/admin`.
- Для редагування товарів виконайте один раз `admin-dashboard-security.sql` у **SQL Editor**.
- Увійдіть за magic-link з пошти адміністратора. Дані в таблицях змінює лише авторизований адміністратор; публічний сайт має доступ лише на читання.
- Для перевірки товару зберігайте посилання на **точну** сторінку моделі у блоці «Перевірені джерела». Не додавайте URL лише категорії чи головної сторінки виробника.
- «Бібліотека джерел» в адмінці містить стартові посилання на Market Dveri, Abwehr, Grand, Papa Carlo, Qdoors і Страж.

### Тестування змін адмінки

- Робоча гілка для доопрацювань: `admin-improvements`.
- Її Preview-деплой у Vercel використовує ту саму базу Supabase, тому редагування даних у тестовій адмінці є реальними змінами каталогу. Для перевірки інтерфейсу не зберігайте тестові дані.
- Банер «Тестова версія адмінки» означає, що код не потрапив у Production; він не означає окрему тестову базу даних.
- Після перевірки інтерфейсу зміни коду переносяться в `master` лише окремим підтвердженим кроком.

## Керування фабриками, колекціями й товарами

1. Один раз виконайте файл catalog-structure-management.sql у **SQL Editor**.
2. В адмінці відкрийте будь-яку модель → вкладка **«Джерела»** → розкрийте **«Керувати фабриками, колекціями та товарами»**.
3. Там можна додавати та редагувати фабрики, колекції й товари-чернетки. Чернетка не потрапляє на сайт, доки не ввімкнете «Показувати товар у каталозі».
4. Фабрику або колекцію не можна видалити, якщо в ній залишилися товари. Спочатку перенесіть або видаліть ці товари.

## Прийом заявок

1. Виконайте файл leads-management.sql у **SQL Editor**.
2. Після цього форми заміру, контакту та прорахунку моделі будуть записувати заявки у таблицю leads.
3. В адмінці: відкрийте будь-яку модель → вкладка «Джерела» → «Керувати каталогом і заявками». Там можна змінювати статуси заявок.

### Telegram-сповіщення

Після збереження заявки сайт може одразу надіслати повідомлення менеджеру в Telegram. У Vercel → **Settings → Environment Variables** мають бути додані:

- `TELEGRAM_BOT_TOKEN` — токен бота;
- `TELEGRAM_CHAT_ID` — chat ID менеджера або робочої групи.

Ці змінні додаються тільки у Vercel, не в Supabase і не в GitHub. Після зміни змінних створіть новий deployment або зробіть наступний Push origin. Токен не можна показувати в листуванні, документах чи комітах.

## Кошик і заявки на прорахунок

- Клієнт може додати кілька моделей до кошика, вибрати кількість та залишити один контакт для прорахунку.
- У заявці зберігаються моделі, кількість, вибрана конфігурація, контактний спосіб та коментар.
- Заявки потрапляють у таблицю `leads`; менеджер працює з ними в `/admin/leads`.
- Публічний сайт не має прав редагувати каталог або читати заявки інших клієнтів.

## Імпорт Qdoors через адмінку

У головному блоці адмінки доступний сканер офіційного каталогу Qdoors. Він допомагає знайти вже наявні та нові моделі, але не робить автоматичних змін у базі.

1. Проскануйте каталог або серію.
2. Відкрийте потрібну модель у вікні звірки.
3. Порівняйте картку виробника з нашою карткою.
4. Позначте «Це наша модель», імпортуйте лише вибрані підтверджені дані або додайте нову модель.

Для кожного імпорту обов’язково зберігайте URL точної картки в `product_sources`.

## Поточний стан каталогу

- У каталозі 363 моделі.
- Усі моделі мають головне фото, опис і щонайменше базові технічні характеристики.
- Декори стають доступними для вибору на сайті лише тоді, коли в `product_variants` додано точне фото саме для відповідної моделі та комбінації опцій.
- Останній загальний звіт: `catalog-quality-overview.sql`; детальний перелік для перевірки: `catalog-quality-audit.sql`.
- Каталог використовує Supabase Image Transformation для компактних прев’ю у сітці; оригінали зберігаються у bucket `catalog-images`.

# Аудит якості каталогу

Для одного простого зведення спершу запустіть [catalog-quality-overview.sql](catalog-quality-overview.sql) у Supabase SQL Editor. Він повертає загальний рядок і показники за кожною фабрикою в одній таблиці.

Для детальних списків проблем запустіть [catalog-quality-audit.sql](catalog-quality-audit.sql) у Supabase SQL Editor. Він нічого не змінює: перевіряє записи товарів і фактичну наявність файлів у bucket `catalog-images`.

Перший пакет після аудиту — [product-specs-seed-priority-15.sql](product-specs-seed-priority-15.sql). Він доповнює характеристики 15 моделей, у яких раніше було лише один або два параметри.

Наступний пакет — [product-descriptions-seed-priority-154.sql](product-descriptions-seed-priority-154.sql). Він замінює лише шаблонні описи 154 моделей на змістовні тексти, сформовані з уже підтверджених даних каталогу.

Для поповнення джерел не використовуйте посилання на головну сторінку фабрики. Наприклад, [product-sources-seed-rodos-grand-batch-01.sql](product-sources-seed-rodos-grand-batch-01.sql) додає прямі картки 12 моделей Rodos Grand; він не призначає фото декорів без окремого підтвердження.

Звіт показує загальну картину, проблеми за фабриками та окремі черги: головні фото, описи, технічні характеристики, декори без фото й відсутні джерела.
