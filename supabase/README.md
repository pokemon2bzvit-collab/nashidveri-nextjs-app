# Supabase для каталогу «Наші двері»

1. Увійдіть на [Supabase](https://supabase.com/dashboard) і натисніть **New project**.
2. Назва: `nashi-dveri`; регіон — найближчий європейський; пароль бази збережіть у надійному місці.
3. Після створення відкрийте **SQL Editor** → **New query**, скопіюйте вміст `schema.sql` і натисніть **Run**.
4. У **Project Settings → API** скопіюйте `Project URL` та `Publishable key` (або `anon` key).
5. Додайте їх у Vercel: **Project → Settings → Environment Variables**. Назви змінних наведені в `.env.example`.

Не передавайте і не додавайте в GitHub `service_role` key або пароль бази даних. Для сайту використовується лише публічний ключ.

Після цього наступним кроком перенесемо 363 моделі та їхні фото в `catalog-images`, а сайт почне брати каталог із Supabase.

## Адмінка каталогу

- Закрита сторінка: `/admin`.
- Для редагування товарів виконайте один раз `admin-dashboard-security.sql` у **SQL Editor**.
- Увійдіть за magic-link з пошти адміністратора. Дані в таблицях змінює лише авторизований адміністратор; публічний сайт має доступ лише на читання.
- Для перевірки товару зберігайте посилання на **точну** сторінку моделі у блоці «Перевірені джерела». Не додавайте URL лише категорії чи головної сторінки виробника.
- «Бібліотека джерел» в адмінці містить стартові посилання на Market Dveri, Abwehr, Grand, Papa Carlo, Qdoors і Страж.

## Керування фабриками, колекціями й товарами

1. Один раз виконайте файл catalog-structure-management.sql у **SQL Editor**.
2. В адмінці відкрийте будь-яку модель → вкладка **«Джерела»** → розкрийте **«Керувати фабриками, колекціями та товарами»**.
3. Там можна додавати та редагувати фабрики, колекції й товари-чернетки. Чернетка не потрапляє на сайт, доки не ввімкнете «Показувати товар у каталозі».
4. Фабрику або колекцію не можна видалити, якщо в ній залишилися товари. Спочатку перенесіть або видаліть ці товари.
